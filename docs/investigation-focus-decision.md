# Investigation focus: selected path and trial basis

## Decision and limitation

The installed optional focus skill starts a clear bounded request from its stated result and delivers the complete requested artifact. When the goal has several plausible outcomes, it offers a few grounded choices. Continuing inquiries can use a human-readable note in a caller-selected local directory separate from evidence sources; Git is optional. The skill preserves direct evidence locators or short excerpts, consequential findings, uncertainty and human corrections. The human approved the guidance-first path on 2026-10-02 after the descriptive comparison, then accepted a correction to reduce setup friction shown by five reported real-use sessions. This decision record does not create an inquiry state API.

Continuity and consistency still depend on the agent following the guidance. A continuing note is a human-owned file, not canonical Pinboard state or an application-validated relation graph. An agent may lose or misrelate a source window, uncertainty, human correction, decision, or document relationship across sessions or outputs. The human accepted that material limitation; `ARCHITECTURE.md` records its consequence and reopening condition. Reopen typed records and application validation if real multi-session use shows such losses despite the saved note and guidance; test the exact failing relationship before adding an owner. The five reported sessions were separate fresh inquiries, so they do not test note-based same-inquiry recovery.

The choice is reversible. Continuing work needs the optional guidance and local note practice, while any later typed record would add validation, persistence and recovery across application and storage owners. A valid record shape alone would not establish that a claim is true or that the agent found the right source. No real-use same-inquiry continuity or compaction benefit has been demonstrated.

## Inquiry contract and ownership

One inquiry can outlive several bounded passes and support independently revised outputs. A pass has a selected question, permitted sources, an effort or time bound, findings, exhausted leads, coverage gaps, a stop reason and a next useful question. It can stop when its bound is reached, a useful answer is available with stated limits, accessible evidence has diminishing value, a necessary source is unavailable, or urgent evidence needs human attention. An urgent finding is reported with its source and uncertainty; it does not authorize remediation, messages or delivery work.

The human selects any continuing inquiry home and output destinations. A bounded request does not require a separate note home. Reading an evidence source does not authorize writing to it or exporting it. The agent may save inquiry notes and drafts in the selected home within the authorized pass; an output elsewhere needs its own destination authority. Confidential originals remain at their source or in the caller's private home. A work-computer trial may return only a human-reviewed sanitized package to this development item. Existing Pinboard containment and trusted-local assumptions apply to its checkout and work root, not automatically to an arbitrary inquiry directory.

The focus skill owns inquiry guidance: starting a clear bounded result directly, narrowing a diffuse question with the human, gathering varied sources, recording what was actually seen, preserving corrections, and resuming from a saved note when the work continues. The note keeps an inquiry identity and evolving purpose, source versions or time windows, direct locators or snippets, observations, inferences, proposals, agreements, contradictions, unknowns, inaccessible or unsearched sources, exhausted leads, human directions, and the evidence used by each output. A later revision makes freshness visible without silently replacing an earlier observation or agreement. A source not accessed is a coverage gap, not a negative finding.

Technical Writing can shape a technical note, leadership summary or other audience-specific prose from the accepted facts. It does not acquire sources, own the inquiry's continuing state, or decide whether an evidence relationship survived resumption. Current Pinboard application modules, ledger, immutable artifacts and delivery attempts continue to own repository work items, accepted briefs, candidate publication and review. In particular, `application.queries`, `application.work_briefs` and `application.artifact_publication` do not resume or publish a continuing inquiry. An inquiry note is not a delivery attempt or an accepted immutable artifact, even if stored near project files. A finding may propose a Pinboard item or an operational change, but that effect requires separate human authority.

## Representative path

A human asks, “Did Harbor's deployment cause checkout delays?” They also mention incident response, a service improvement plan and a leadership update. Before choosing an output for them, the agent summarizes a few grounded results it could pursue, such as a bounded incident diagnosis, an observability plan, or a leadership decision brief. The human selects the diagnosis and an effort bound. The agent then looks broadly enough to challenge that focus: service catalog, deployment record, repository history, traces, latency and queue dashboards, and a team note, while tracking which sources were actually available.

The first pass finds a latency rise after deployment and one trace sample from a single region. It records the dashboard's exact window and a trace locator or short excerpt so the human can check the observation directly. Temporal correlation is observed; deployment causation remains an inference. A deployment-code lead is dismissed when the changed code does not touch the slow operation. The queue dashboard is listed but inaccessible and the team note is discoverable but unsearched at the bound. The agent saves those limits, the dismissed lead, a technical note version 1 and the next question in the inquiry home. The human sees the consequential finding, what still needs a choice or acknowledgement, and the checkable sources before the longer research detail.

On a later session, the agent reads that note, preserves the earlier windows and resumes without treating the chat as the only memory. The human corrects the direction: investigate whether an upstream retry policy amplified load, and prepare a leadership summary. A second bounded pass reads a newly available queue snapshot, a retry-policy record and the deferred team note. The queue snapshot covers a later window, so it does not prove the original deployment hypothesis. The policy record conflicts with the team's “no retry change” note; both claims and their locators remain visible. The leadership summary version 1 gives the observed slowdown and backlog, labels retry amplification as plausible, names the disagreement and mismatched windows, and asks the human to acknowledge or correct the interpretation before recommending a limited measurement. The technical note remains version 1 until deliberately revised. An urgent growth in errors would be surfaced promptly with its window and source, without silently changing the agreed pass or production settings.

This path describes the continuing-inquiry contract. The installed skill guides it, but the five reported real-use sessions did not resume the same inquiry from a note. A later natural-use trial must test whether saved evidence and document relationships survive that boundary.

## Comparison evidence and alternatives

Checkpoint 3 compared ordinary inquiry, focus guidance, and guidance plus a strict structured evidence record in two held-out fictional cases: urgent payment delay and cross-service billing. Each arm had one three-turn run per case with the same Luna-high setting, scripted human turns and source access. The cases and targeted measures were registered before the final guidance edit in `evals/behavioral/data/investigation/sets/heldout.json`; detailed run and assessment records remain in the private attempt evidence. The accepted candidate is commit `5c3d5b0b1ac068a08dea7001c1a453c170b51f6e`. The accepted checkpoint-3 result and independent review are descriptive evidence, not proof of performance on real work.

| Observation | What it supports | Limit |
| --- | --- | --- |
| Guidance answers supplied original-source locators and relevant time windows in both cases, where ordinary answers often pointed to the agent's own note. Guidance retained the human's chosen output and the correction dismissing a red herring. | Try focus guidance and a saved note as the minimum reversible path. | The urgent guidance run missed one cross-source breadth measure. Direct links did not make every conclusion complete. |
| Strict structured records were produced and validated on every turn. They preserved useful distinctions, including the billing acceptance gap versus missing rows. | Record shape can make some facts and relations inspectable. | Structured answers did not consistently improve conclusions over guidance. One tuning answer added a dashboard date that the source did not contain; shape validation did not catch it. The urgent structured run also took longer. |
| Raw traces showed a fresh identity and successful saved-note read in all six held-out runs. | The controlled fresh-session read mechanism worked in those runs. | The blind answer assessor sometimes marked recovery false because it saw replies, not tool events. No compaction occurred. Neither these traces nor the answer scores prove real multi-session usefulness, reduced human effort, or reliable recovery of meaning. |

Targeted answer counts were 5/9 and 4/9 for ordinary, 7/9 and 8/9 for guidance, and 8/9 and 7/9 for structured across the urgent and cross-service cases respectively. These are one-run judgments, not repeated-run variance or a superiority estimate. Three scripted human turns were required in every run; actual human editing effort was not measured. The urgent case required separating a 09:00–09:30Z dashboard rise from a retry-load inference before reducing retries. The cross-service case required keeping a 6,000-ID acceptance gap distinct from 300 missing billing rows and rejecting a later UI timestamp change as the cause of earlier gaps. Those source relationships explain the value of direct checkability and retained human choices more than the counts alone.

Three routes remain distinguishable, with one selected for the first trial:

- **Selected optional guidance:** The skill and caller-selected note guide discovery, resumption, human choice and output relations without an installed state machine. Falsify its adequacy with real multi-session evidence of lost decisions, source context or document relationships despite the note. A repeated, preregistered comparison where it loses original-source grounding or human choice while another route reliably retains them would also challenge the choice.
- **Conditional structured local records:** Typed inquiry, pass, evidence and output-relation records could validate shapes and reload them from the selected home. This crosses application contracts and storage effects and requires a separate architecture decision. Reopen it for an observed continuity or relationship failure that a validator can actually prevent, while checking that it can represent changed direction and uncertainty.
- **Conditional application-backed support:** An installed use case and narrow CLI or MCP entry could own pass transitions, evidence identities and output registration. It crosses domain, application, adapter and interface owners. Reopen only for a named supported failure that needs enforceable sequencing or identity beyond guidance and a local record, then prototype the failing mechanic before installing that larger path.

The current comparison stops at this descriptive result. Earlier experimental prompts and costs remain historical evidence. Further paid comparisons are not required by this decision checkpoint.

They report useful evidence discipline across varied tasks and recurring friction when a clear request was delayed by mandatory inquiry-home selection or returned in a narrower format than requested. The formal collector was not run. The returned relations and chronology are reconstructions; original transcripts and source locators were withheld, and costs are unavailable. A private trial synthesis records the relation coverage and limits without putting company findings in public source.

The current correction keeps the optional collector available for later use and registers one fictional bounded request beside the existing diffuse-goal case. Its controlled Luna-high run is descriptive evidence for the corrected startup and complete artifact, not a statistical comparison or proof of same-inquiry recovery. Later natural use can test whether a saved note preserves decisions, source windows and output relationships across sessions. This decision changes guidance and documentation, not Pinboard delivery behavior or application state ownership.
